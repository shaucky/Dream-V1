# Dream

Dream 是一个 2D 游戏引擎，由 **Dream Studio**（项目编辑器）与 **Dream Engine**（运行时框架）两部分组成。
前者负责可视化编辑，后者负责把编辑结果变成可发布的游戏。

引擎采用 **ECS**（Entity-Component-System）架构，运行在 **AIR 50.0** 之上，通过 Stage3D（Starling）
做硬件加速渲染，用 Box2D 提供 2D 物理，脚本语言为 ActionScript 3.1。

## 关于本项目

本项目是**黑箱 vibe coding 的产物**：代码由 AI 代理在人类的高层指令下生成与迭代，人类开发者并未逐行审查。
它服务于「把想法快速变成能跑的游戏」这一目标。

**使用预期**：项目仍在开发阶段，架构与 API 可能随时大幅调整，不保证代码质量、稳定性与向后兼容，
不建议直接用于真实项目；文档与注释也可能落后于实现。欢迎通过 issue 或讨论反馈问题与建议。

## 组成部分

### Dream Studio

基于 [Avalonia](https://avaloniaui.net/) 构建的跨平台项目编辑器，提供完整的可视化编辑能力：

- **可停靠工作区**：面板支持拆分、标签页合并与浮出为独立窗口，布局随使用习惯自由调整。

- **内嵌运行视口**：把 **ADL**（AIR Debug Launcher）启动的引擎窗口直接嵌入编辑器，边运行边编辑，
  无需在两个窗口之间来回切换。

- **双向实时通信**：Studio 与引擎通过 TCP 交换消息（场景、层级、Inspector、资源索引、构建等），
  引擎侧的状态变化会实时回推到编辑器界面。

- **运行期可编辑**：运行状态下依然可以改值、增删组件、执行撤销/重做，改动立即生效，方便调参。

### Dream Engine

基于 [AIR](https://airsdk.harman.com/) 的游戏开发框架，采用 ECS 架构，
提供易维护的框架设计与现代的游戏引擎开发体验。引擎集成了若干开源库，包括 Starling 与 Box2D。

- **ECS 核心**：`Element` / `DreamComponent` / `DreamSystem` / `World`，组件在编译前自动扫描注册，
  新增组件只需继承基类并放在源码目录下。

- **渲染**：基于 Stage3D 的精灵渲染，支持精灵图集、相机与缩放，以及屏幕空间 / 世界空间 /
  相机空间三种 UI 画布模式。

- **UI 体系**：`RectTransform` + `Canvas` + `CanvasScaler` 的布局与自适应缩放，
  内置 `Image` / `Text` / `Button` / `ScrollView` / `Mask` / `Layout` 等控件。

- **2D 物理**：Box2D 封装，含刚体、盒/圆碰撞体、射线检测与碰撞回调。

- **动画**：`AnimationClip` 关键帧片段 + `AnimatorController` / `AnimStateMachine` 状态机，
  支持过渡条件与 Exit Time。

- **音频**：音频管理器、混音组、音源与听者，支持运行期实时调整音量。

- **输入**：键盘输入管理与输入系统。

- **场景与资源**：场景序列化与读档、Prefab 实例化与还原、资源 GUID 引用与 `resource.manifest.json` 清单。

## 编辑器功能

除场景视图外，Dream Studio 提供以下面板：

| 面板        | 用途                                            |
| --------- | --------------------------------------------- |
| Hierarchy | 查看元素层级，支持创建、删除、重命名等操作                         |
| Inspector | 查看与修改元素及组件的字段值，支持增删、启停与粘贴组件                   |
| Project   | 浏览项目资源，处理 `.meta` 与 GUID、图集打包、纹理切片，并支持拖拽到其他面板 |
| Clip      | 曲线编辑动画片段（`.dmclip`）：轨道 × 时间轴，增删关键帧与编辑数值       |
| Animator  | 编辑动画状态机（`.dmanimator`）：状态、参数与过渡条件             |
| Audio     | 调整主音量与内置混音组音量，实时作用于正在播放的声音                    |
| Console   | 查看引擎运行日志                                      |
| Build     | 配置并执行发布构建                                     |

**资源引用采用 GUID**：`source-path` 下的每个文件都伴随同名 `.meta` 文件，记录 GUID 与资源类型，
文件重命名或移动不会破坏场景中的引用。**Build** 面板支持 Windows、Android、iOS 与命令行四种标签页，
目前 Windows 输出桌面 bundle、Android 输出 APK / AAB 已接通，iOS 尚未接通。

## 快速上手

1. **准备 AIR SDK**：Dream Engine 依赖 Harman 提供的 AIR SDK。因其许可不允许再分发，
   需要你自行获取安装，然后在 Studio 的 **Help → Settings** 中配置路径。
2. **打开工程**：用 Dream Studio 打开 Dream 工程，即可开始编辑、运行与调试。
   引擎会在 Studio 启动流程中自动编译，无需手动执行编译命令。
3. **发布构建**：在 **Build** 菜单中按目标平台配置并打包。打包 AAB 时还需在设置中额外指定 Android SDK 路径。

> 编辑器目前以 Windows 为主要运行平台（依赖 Win32 窗口嵌入）。

## 发展方向

### V1：完整的 2D 游戏开发能力

目标是让一个 2D 小游戏从编辑到发布可以只用 Dream 一套工具完成，发布平台为 Windows 与 Android。

| 能力                                              | 现状                                            |
| ----------------------------------------------- | --------------------------------------------- |
| ECS 核心（Element / Component / System / World）    | 已具备                                           |
| 渲染（Stage3D 精灵、图集、相机、三种画布模式）                     | 已具备                                           |
| UI（RectTransform / Canvas / CanvasScaler 与常用控件） | 已具备                                           |
| 2D 物理（Box2D 刚体、碰撞体、射线、碰撞回调）                     | 已具备                                           |
| 动画（关键帧片段与状态机）                                   | 已具备，sprite frame动画待补齐                         |
| 音频（管理器、混音组、音源与听者）                               | 已具备                                           |
| 输入                                              | 键鼠输入已具备，触摸与多点触控待补齐                            |
| 基础工具（计时器 / 延迟调用、补间缓动、字体导入）                      | 待补齐，其中补间缓动的实现方式待评估                            |
| 场景与资源（序列化、Prefab、GUID 引用与资源清单）                  | 已具备，场景管理待补齐                                   |
| 构建发布                                            | Windows 与 Android 已接通；Android 的权限与屏幕方向配置入口待补齐 |
| 编辑器（面板体系、运行期编辑、撤销重做、发布构建）                       | 已具备                                           |

### V2：自定义渲染层与 3D

V2 计划把渲染层从现有实现迁移到自研的渲染层，利用 **AIR 51.0** 提供的 float 单精度浮点数能力，
并在此基础上把引擎从 2D 扩展到 **3D** 开发。渲染、材质与相机等模块都会随之优化。
